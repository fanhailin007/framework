# 前端框架文档中心

本文档体系用于把当前 Vue 模板沉淀为可支撑大规模应用系统开发的前端框架。文档面向项目负责人、前端开发、后端接口开发、测试和运维部署人员。

## 阅读顺序

1. [整体架构](./architecture.md)：先理解框架分层、启动流程和目录职责。
2. [路由与菜单协议](./router.md)：理解页面、菜单、面包屑、多标签和权限入口如何协同。
3. [认证与权限](./auth.md)：理解登录、token、用户信息、角色权限和按钮权限。
4. [接口规范和错误处理](./request.md)：理解 API 返回结构、请求封装和错误策略。
5. [业务模块开发规范](./module-standard.md)：新业务模块按此组织目录和代码。
6. [组件开发规范](./component-standard.md)：公共组件、业务组件和示例组件按此边界维护。
7. [代码生成使用说明](./codegen.md)：使用 Plop 生成 CRUD 模块，并了解后续扩展方向。
8. [构建、环境变量、部署](./deployment.md)：了解本地、测试、生产环境的配置和发布要求。

## 文档维护原则

- 文档必须跟随代码变更同步更新，尤其是路由元数据、接口返回结构、权限协议、构建配置。
- 新增通用能力时，先判断它属于框架层、业务层还是示例层，再更新对应文档。
- 文档中的协议示例应保持可复制、可落地，不写只表达意图的空泛说明。
- 当代码与文档冲突时，以代码为当前事实，但应立即修正文档或补充迁移说明。

## 当前模板定位

当前项目是一个基于 Vite、Vue 3、TypeScript、Pinia、Vue Router、Element Plus 的中后台模板。它已经包含布局、主题、多标签页、权限、动态路由、请求封装、Mock、PWA、代码生成和大量业务示例。

面向大规模系统开发时，推荐将其定位为：

> 企业后台前端框架内核 + 多业务模板 preset + 示例工程。

不建议把 `src/views` 下所有演示页面直接复制到每个业务系统。框架化改造时应优先剥离演示代码，保留稳定的基础设施、组件协议和开发规范。
